# LIHPS Askling Video v0.3.0 · iPhone web app

A static web app for markerless analysis of one or two side-on videos. It uses MediaPipe Pose Landmarker Full to estimate hip, knee and ankle landmarks and Mediabunny/WebCodecs to decode source frames in presentation order. Each video stays on the device. The web app downloads the decoder, model and runtime on first use.

## Process one or both legs

1. Assign an original camera clip to **Left video** or **Right video**. Either input is sufficient to start. Add both clips when you want a left/right comparison.
2. Use the two rotation buttons to orient each preview. Leave **First raise is practice** off for both clips. The setting is per leg.
3. After selecting a file, its card shows a frame-rate estimate from the file timestamps. After processing, it also shows the measured decoded frame rate. Tap **Process left video**, **Process right video** or **Process both videos**, according to the selected files. Leave the app open while it decodes and analyses the selected clips. With one clip, the other leg and comparison ratios show a dash. If you later add the second clip, the action changes to **Process both videos** and runs both selected files. The progress message shows the current side, frame count and video time. You can cancel analysis.
4. The set summary uses at most three eligible raises, ranked by the sum of descending ROM and peak-speed ranks with equal weight. Ties favor higher ROM, then higher speed, then the earlier raise. Unbraced clips use hip (thigh) metrics and braced clips use whole-leg metrics. Each repetition shows its selection status, and **Exclude from set** lets the examiner remove an otherwise eligible raise. Read the **Set summary**, then expand any raise under **Per repetition** for its individual values and QC. **Show peak frame** brings the peak frame and model overlay into view. Use the slider to move across the clip. **Previous frame** and **Next frame** move exactly one decoded frame. The counter uses one-based frame numbers.
5. Use **Next flagged frame** to jump to the first frame of the next pending stretch. The message shows the reason for the current frame. Step through a stretch to inspect it. After inspection, choose **Mark reviewed** or **Mark stretch reviewed** to remove it from the queue. These actions acknowledge the flags and leave the analysis QC in place.
6. To adjust a landmark, open **Correct landmarks on this frame**, choose hip, knee or ankle, and tap the point on the preview. The app marks the results as pending. Tap **Recalculate with corrections** to apply edited landmarks to all calculations for the selected leg. The button uses the existing landmarks and preserves your corrections. The displayed revision and corrected-frame count confirm their inclusion. Use **Reset frame** to recover the model's landmarks for the displayed frame. Corrections affect the selected frame only. The chosen joint stays active while stepping through that clip. Each edit refreshes the review flags. Measurements update after recalculation. Export stays disabled while changes are pending. Running a fresh model pass preserves edits at matching source timestamps.
7. Export the repetition CSV before closing or replacing the videos. Export repetition CSV and, when needed, frame data before a reload. The frame export includes landmarks, the original model coordinates for edited frames, timing, the applied revision and selection status. No recordings, landmarks or results are retained across reloads.

## Braced knee and review flags

**Braced knee for this leg** can be toggled per clip. It uses the hip-to-ankle line to find repetitions and locate peak preview frames. If knee tracking fails within a raise or has a knee-related review flag, the app withholds thigh, shank and knee measurements for that raise. Hip-to-ankle angle and speed stay available when their own QC passes. When knee measurements are available, knee flexion at peak still refers to the peak of the thigh trace. The CSV records the mode, the basis of the peak-frame timestamp, and any knee-specific QC.

For unbraced clips, the queue uses projected thigh and shank lengths separately. Braced clips also use projected hip-to-ankle length and place knee-only stretches behind hip, ankle and timing issues. The length threshold is the larger of 3 scaled median absolute deviations and 12% of the median length. Missing or low-confidence points, isolated jumps relative to neighbouring frames, and timestamp gaps can also trigger review. Consecutive flags of the same priority are grouped. These are screening heuristics, and genuine out-of-plane motion can change projected length.

## Interpretation

Thigh and shank measurements use hip-to-knee and knee-to-ankle orientations relative to rest. Hip-to-ankle excursion is a separate whole-leg measure. Knee flexion is the angle between the thigh and shank, with a straight line at 0°. The app reports knee flexion at peak thigh elevation and maximum knee flexion during each raise. Results are ordered hip, knee, shank and whole leg. These 2D measures assume a stationary side-on camera and movement close to the image plane.

The app smooths valid angle runs using a local quadratic fit, with a timestamp window of ±38 ms or about ±3 frame intervals, whichever is larger. Peak velocities are positive central differences around the upward phase. Automatic quality flags identify large landmark jumps, invalid points or timestamps inside a raise, and incomplete returns. They cannot detect every plausible-looking misplaced point or wrong-leg estimate. Raises with repetition-level QC failures, practice raises and examiner exclusions are excluded from the set means. The best-three rule is applied to the remaining eligible raises. Review-queue flags direct inspection and remain distinct from repetition-level eligibility. Where a comparable value exists for both sides, the summary reports Left ÷ Right × 100. Knee flexion is shown in degrees on each side. Speeds from clips below 100 decoded fps are marked preliminary.

## Timing and starting reference

Analysis uses the decoded source timestamps by default. File-frame-rate estimates are sampled on upload and decoded frame rate is displayed separately after processing. File timing cannot prove the camera acquisition rate after retiming or dropped-frame export. If a slow-motion file retained every original captured frame, **Video timing for the selected leg → Use confirmed capture fps** allows the examiner to specify the original rate. This explicitly uses one captured-frame interval per source frame for analysis. It does not create missing frames. Recalculate after a timing change. The CSV records file timing, decoded fps, effective analysis fps and the selected time basis. Frame review always seeks the original source timestamps.

The automatic resting reference uses the stable start before the leg begins lifting, up to half a second. This accommodates clips where the first lift starts sooner. If the reference needs adjustment, navigate to an extended resting frame, choose **Use this frame as resting reference**, then recalculate. **Use automatic resting reference** restores the automatic calculation.

If processing fails, the app retries with software decoding. Failures identify the leg, processing stage and frame, and the other leg can continue. A successful existing analysis is retained until a replacement finishes.
